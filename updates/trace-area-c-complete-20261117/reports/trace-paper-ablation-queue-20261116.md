# Finite Seven-Task Ablation Queue

One manually STARTed CPU controller adopts the already running Object process
by its exact original unit/PID/invocation, without restart. It dispatches only
the seven frozen tasks in their fixed order, one GPU prediction then separate
CPU score each. It creates no recurring automation, cron or new monitor agent.

The manually inspected controller START binds its own code, CPU scorer,
existing model PLAN, task order and the exact adopted identity. For every new
child it verifies the actual process argv/cwd/environment/invocation and
effective resource caps before issuing that phase's exact typed START. A new
CPU_GT grant is conditional on sealed predictions AND the same actual retained
successful GPU exit. No GT enters prediction or calibration processes.

The finite queue has no retry/resume/overwrite path. Failed original bytes and
units remain; repair requires changed code, a new source freeze/root and a new
manual START. The child/runtime stop on any mismatch. The existing original
GPU lock serializes actual model execution; GPU12GiB/1GiB and CPU4GiB/1GiB,
threads1,OOMstop/Restartno remain fixed.

Controller completion means only these seven diagnostic tasks completed. R04,
time-only finegrid, proper standalone efficiency, official TENT and manuscript
delivery are separate remaining obligations, not implicitly completed here.
